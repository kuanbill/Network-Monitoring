# 左側設定與全量匯入設計

## 使用方式

左側導覽新增「設定」，沿用現有對話框。上方保留「更新頻率」與它自己的儲存按鈕；下方是「匯出設定」「匯入設定」。移除總覽頁底的舊設定按鈕，但保留兩種更新間隔及最後同步時間。既有「郵件通知」仍獨立。手機版須能使用設定入口、鍵盤操作與清楚的錯誤和焦點狀態；文字使用繁體中文。

匯入為**全部取代**，不是合併：檔案裡的主機清單、更新頻率及郵件設定取代目前設定，未列入的主機會移除。選取現有匯出的 JSON 後，先由後端驗證並預覽，顯示新增、更新、移除及不變的主機數，可查看將移除的主機，並列出匯入後的兩種間隔、郵件啟用狀態與 SMTP 目標／收件人變更，以及需重新輸入憑證的項目。空主機清單允許，但清空時須明確顯示警告。預覽中可匯出目前的無密碼備份；只有按下「確認取代全部設定」才保存。取消、選錯檔案或驗證錯誤不影響現況。更新頻率的表單與匯入確認分開；匯入後重新載入頻率表單與總覽，不將未儲存的頻率草稿寫回。

## 格式與憑證

- 沿用既有 `netword-monitor`、`version: 1` 匯出格式，三個區段 `settings`、`hosts`、`notifications` 必備；匯出繼續不含 Agent Token、SMTP 密碼或運行歷史，但仍可能包含內部 IP、HTTP 網址及郵件位址，不適合公開。接受當前及新增 Docker／網站旗標之前的 v1 匯出；缺少的相容欄位使用原格式預設值，不從目前設定合併。接受當前格式產生的主機 `id`，但匯入時以正規化 IPv4 對應目前主機並保留同 IP 的本機 ID；全新 IP 由本機配置 ID，不讓檔案的 ID 指向不同的本機主機。
- 整檔驗證後才允許預覽。拒絕未知版本、未知欄位（含 `agent_token`、`password`、`password_set`、`delivery` 等憑證或狀態欄位）、重複 JSON 欄位、重複 IP、非法 Unicode、非有限數值和不符合既有主機、HTTP URL／SMTP 驗證規則的內容。錯誤可指出區段或主機筆數，不回顯任意輸入值或原始 JSON。檔案大小最多 40 MiB，以涵蓋應用程式本身產生的 v1 匯出（最多 256 台、每台 16 項檢查、每個 URL 最長 2048 字元）；只在預覽端點提高大小限制，最多一個匯入本文解析／預覽工作同時進行，原有 API 保持原限制。前端直接送出檔案原始位元組，不先經 `JSON.parse` 或容錯解碼；後端嚴格以 UTF-8 讀取，接受 UTF-8 BOM。
- 本機 Agent Token 只在**同 IPv4、同 Agent 連接埠**時保留；設定名稱、一般檢查的變更不影響保留。若匯入要求啟用 Agent 但無可保留的 Token，該主機仍匯入，Agent 暫不啟用，依賴 Agent 的 Docker 檢查也暫停用；預覽明確列出需在原主機編輯功能重新輸入 Token，並指出要重新啟用的檢查。獨立網站及其他一般檢查不受缺 Token 影響。若匯入檔原本宣告了不合法的旗標組合，例如 Agent 關閉但 Docker 開啟，直接拒絕而非自動修正。
- 本機 SMTP 密碼只在正規化主機名稱（不區分大小寫）、連接埠、TLS 模式和登入帳號皆相同時保留。接收者、寄件者等以檔案為準；若匯入要求通知開啟但新帳號需要密碼而無法保留，保存其非機密設定並停用通知，在預覽提示重新輸入密碼和啟用。其餘原本不合法的通知設定仍拒絕；允許原功能已支援的免驗證 TLS SMTP。匯入、預覽不發測試信、不測連線、不改 Agent 安裝或防火牆。

## 套用、儲存與版本相容

- 增加兩個受既有 Host／Origin 防護、Windows 工作階段路徑保護的本機 API：`POST /api/config/import/preview` 驗證原始匯出 JSON 並回傳安全摘要及一次性確認碼；`POST /api/config/import/apply` 只接受該確認碼並原子套用。只留一份待確認預覽、最多 10 分鐘，下一次成功預覽替換前一份；任何真正的主機、頻率、郵件設定變更（含只改密碼）都使預覽過期，即使值日後改回亦然。量測更新或寄信狀態變更不影響預覽。多視窗競態或已過期以 `409` 提示重新預覽；保存失敗不套用且可於有效期內重試或重新預覽。
- 為避免三個 JSON 分開寫入造成部分成功，首次成功匯入時以同目錄的私密暫存檔、`fsync` 與原子替換保存單一 `configuration.json`，包含三個區段與保留的本機憑證；完成前不變更執行中設定。之後載入及一般編輯都以這個檔案為準，在同一套鎖與持久化路徑協調三種更新，避免互相覆寫。尚未匯入的安裝維持原本三個檔案的讀寫行為。舊檔保留，不再更新；文件說明 Docker／桌面設定目錄遷移、匯入後的備份與 Windows 手動維護旗標方式，不把舊檔稱為最新備份。不存在新檔才讀舊檔；新檔損壞須明確中止，不可無聲回退舊設定。不要直接以舊版讀取曾成功匯入的資料目錄；舊版不認得單一設定檔。
- `configuration.json` 屬機密，檔案權限不得比現有設定寬，禁止提交 Git、映像、安裝包與支援日誌。保留已儲存的舊檔不自動刪除；提示若需完整還原含密碼的設定，先離開管理端，備份其受保護的整個 `data` 目錄，而非把密碼加進匯出檔或沿用舊檔。Windows 桌面端保留獨立資料目錄，不和 Docker 共用。
- 保存成功才一次切換記憶體狀態，清掉舊的主機量測及通知事件，作廢舊的待送信與重試，喚醒下一輪量測。匯入前開始的主機量測不能覆寫新設定；在匯入前就已開始的 SMTP 嘗試無法撤回。匯入不重啟程式、不直接觸發測試信，也不修改程式版本號。

## 驗收

隔離測試驗證現有 v1 匯出可匯入、完整替換／空清單、憑證只按符合的目標保留、缺憑證時的停用提示、錯誤／過期／重複套用／多視窗設定變更、儲存失敗與重啟後一致、一般設定修改與 Windows 路徑隔離。用瀏覽器驗證左側與手機入口、更新頻率、匯出、取消／確認匯入、無需上傳密碼及安全顯示不可信名稱。測試不讀寫正式設定、不接觸正式 Agent 或 SMTP。部署、推送、合併、安裝包和版本調整不包含在此變更中。
